# 🛡️ AWS Cloud SOC Detection Lab

A hands-on cloud security and SOC monitoring project built in AWS to demonstrate practical skills in Linux hardening, SSH security, host firewall configuration, audit logging, security event detection, and incident investigation.

## 🎯 Project Objective

The goal of this project was to deploy and secure an Ubuntu Linux server in AWS and build host-level monitoring capable of detecting security-relevant changes.

This lab demonstrates skills relevant to:

- SOC Analyst

## 🔐 Security Hardening

The Linux EC2 instance was hardened using several defensive controls.

### SSH Security

The SSH configuration was validated to ensure:

```text
PermitRootLogin prohibit-password
PubkeyAuthentication yes
PasswordAuthentication no
```

This reduces exposure to password-based attacks and prevents password-based root access.

### Host Firewall

UFW was configured with a default-deny inbound policy while allowing SSH access.

```bash
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose
```

Result:

```text
Status: active
Default: deny (incoming), allow (outgoing)
22/tcp (OpenSSH) ALLOW IN
```

## 🔎 Linux Audit Monitoring

Linux `auditd` was enabled to provide host-level security monitoring.

Service validation:

```bash
sudo systemctl is-active auditd
```

Result:

```text
active
```

Audit rules were configured to monitor critical security files:

```text
-w /etc/passwd -p wa -k identity_changes
-w /etc/group -p wa -k identity_changes
-w /etc/sudoers -p wa -k privilege_changes
-w /etc/ssh/sshd_config -p wa -k ssh_changes
```

These rules detect changes involving:

- User accounts
- Linux groups
- Privilege configuration
- SSH server configuration

## 🚨 Detection Test — Account Creation

A controlled security event was generated by creating a temporary Linux account.

```bash
sudo useradd phase4test
```

The resulting audit events were investigated with:

```bash
sudo ausearch -k identity_changes -ts recent
```

The logs successfully identified:

```text
comm="useradd"
exe="/usr/sbin/useradd"
key="identity_changes"
```

The audit records also showed modifications to:

```text
/etc/passwd
/etc/group
```

This demonstrated that the monitoring controls could detect security-relevant identity changes.
